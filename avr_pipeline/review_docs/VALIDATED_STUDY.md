# Validation-corrected free study

Decision recorded on 2026-11-09 before observing any 3B or 7B repair outcomes.

The replacement cohort comprises hosted Gemma 4 26B A4B and local Qwen2.5 Coder 0.5B, 1.5B, 3B and 7B, all using Q4_K_M weights for the local models. Google reported daily limits of 20 requests for Flash 3.6 and 500 for Flash Lite. Those limits cannot cover the full experiment in one day. The local replacements remove API quota dependence; they were chosen for access and resource fit, not repair scores. Previous Gemini runs remain historical evidence.

This is a separate study of the corrected implementation, not an extension silently pooled with commit `12f7847`. It uses all four pinned subjects, all seven conditions and three repetitions: 420 cells. Reply caps remain 8,192, with temperature 0.1, compact context, review-2 library bytes and the unchanged test classification policy. Exact model revisions, checksums and inference arguments are recorded. No independent preregistration or human guidance review is claimed.

Four models belong to one family. Their quantized CPU implementations and the hosted model use different hardware and operating systems. Within-model factorial contrasts are the primary comparisons; cross-model rates do not establish an architecture-only effect. The public GitHub runners are standard Linux machines, without paid or larger runners or API secrets. Checksum-verified public weights and scanner archives use the included cache allowance, without expanding its limit. Each compressed evidence archive is capped at 1 MiB and retained for one day. Source clones and scanner databases are excluded; prompts, responses, patches, test outputs and SARIF are retained losslessly.

The Windows Pylint crash measurements are excluded by the derived analysis without changing raw artifacts. Windows uses the official pure Python isort 9.0.2 build in a separate environment. Validator failures now interrupt a run as missing evidence instead of becoming patch-quality failures. Target dependency environments are recorded by the corrected runner.

CI logs also exposed the earlier 180-second local HTTP read timeout canceling replies at approximately 4,500 generated tokens, before the common 8,192-token cap. All final local cells now use a 3,600-second wait. Earlier local runs are retained under `local-timeout180-pilots` and excluded from the primary comparison; the whole local matrix is replaced independently of pilot scores. The earlier source fingerprint is compatible only for hosted Gemini-provider runs, because the changed local HTTP method is never invoked there. Original hashes remain visible in the configuration table. Interrupted cells are retained, never counted as zero repairs. Acknowledged generations are audited across saved interruption history; resuming a finding cannot silently reset its attempt allowance. The older `12f7847` validator implementation is not covered by this compatibility rule.

Independent human sign-off and Zenodo author details are deferred at the user's request; the professor will supply them later. No DOI or expert-review provenance is invented.

The evidence audit also found transient Windows file locks in the OneDrive workspace. Some atomic JSON saves failed and the older runner recorded empty-attempt errors as unsuccessful findings. `review/evidence_io.py` now retries identical serialized bytes for up to 30 seconds in the execution wrapper. This changes file I/O only; the core prompts, model settings, patching, gates and tests retain their declared fingerprints. The adapter hash and actual execution settings are recorded. Any trial containing an evidence-save failure is excluded independently of its score, with raw files (including pending JSON) retained in `evidence-storage-audit.json`; a fresh trial is required because consumed replies cannot safely be reconstructed. Healthy Linux runs and earlier healthy Windows runs remain comparable. The particular process holding a file lock has not been identified.

The subsequent continuation correction is core commit `bb43ccd`: it changes `review/runner.py` and adds `review/continuation_state.py`, with new fingerprints in the declaration. It preserves already acknowledged rejected replies, reconstructs their exact refinement state, and requests only the remaining allowance after a service outage. Every carried reply links to hashed immutable original evidence; duplicates are not counted as new generations. Changed prompts/source, invalid references and uncertain storage failures stop continuation. Baseline behavioral evidence is retained rather than overwritten on resume. Twenty canned-response comparisons against `a4922a2` establish unchanged normal prompts, patches and outcome counters; interruption tests cover all five gated conditions, malformed/blocked/limited replies, two outages and cap exhaustion. This is bounded regression evidence, not a proof for arbitrary programs. Healthy prior executions remain compatible with their original fingerprints, through the explicit continuation-only declaration. No completed trial is retried to obtain a better score.
